# MVP: Scope & Prioritization (Simplified for MVP Phase 1)

Overview
This document defines the minimal viable product (MVP) scope, prioritized features, acceptance criteria, and a short roadmap for the Elsa-like AI marketing assistant, inspired by https://www.m1-project.com/ and the provided ICP PDF: [`docs/Ideal customer profile Nomad Foundr.pdf`](docs/Ideal customer profile Nomad Foundr.pdf:1). This version reflects a highly simplified, Supabase-first architecture, leveraging a Next.js SaaS starter template and OpenRouter for LLM integration.

Goals
- Deliver a working ICP generator that produces evidence-backed reports with provenance and PDF export.
- Provide core content and ad generation tied to ICP outputs.
- Gate premium features behind payments and deliver a smooth onboarding flow using a SaaS starter template.
- Keep ops low and costs under $1,000/month for initial scale (1k–5k MAU) by maximizing Supabase.

Sources & assumptions
- Primary product reference: https://www.m1-project.com/
- Example ICP and requirements derived from: [`docs/Ideal customer profile Nomad Foundr.pdf`](docs/Ideal customer profile Nomad Foundr.pdf:1)

- Preferred stack choices (user): Vercel + Supabase, OpenRouter for LLMs, `pgvector` for vector DB.

MVP Principles
1.  **Evidence-first:** Every claim must link to source snippets and URLs (provenance), stored in Supabase Postgres.
2.  **Fast-to-market:** Favor managed services (Supabase ecosystem, Vercel) and SaaS starter templates that reduce ops and accelerate development.
3.  **Cost-aware:** Optimize LLM usage (via OpenRouter) and utilize Supabase `pgvector` to keep costs low.
4.  **Extensible:** Build adapter layers for swapping LLM providers (already done for OpenRouter) and maintain modularity for future growth.

Must-have features (MVP Phase 1)
1)  **User onboarding & authentication:**
    -   Email sign-up, verification, password reset (leveraging SaaS starter UI, backed by Supabase Auth).
    -   Basic project/workspace creation via Next.js frontend interacting with Supabase Edge Functions.
    -   Subscription management and billing flows (via SaaS starter UI, integrating Stripe + Razorpay).
2)  **ICP Generator (core):**
    -   Accept seed inputs: company name, URL, industry, short description.
    -   Retrieval-augmented generation (RAG) pipeline:
        -   Web sources and user-uploaded docs ingested and indexed by Supabase Function workers into Supabase Postgres with `pgvector`.
        -   OpenRouter (via LLM Adapter) for LLM prompting that outputs structured ICP sections (Segment, Persona, Jobs, Goals, Channels, Sources).
    -   Attach source snippets and URLs for each generated claim (provenance stored in Supabase Postgres).
    -   Export ICP as PDF and JSON (generated by Supabase Functions, stored in Supabase Storage).
3)  **Content & Ads generator (basic):**
    -   Short-form captions, ad copy, and a 3-variant ad set per ICP (powered by OpenRouter via LLM Adapter).
    -   Basic channel-optimized outputs (LinkedIn, Instagram, Facebook).
4)  **Payments & gating:**
    -   Stripe Checkout for cards (integrated via SaaS starter).
    -   Razorpay or UPI for Indian buyers (custom integration).
    -   Subscription / one-off purchase gating, managed by Supabase and frontend logic.
5)  **Admin dashboard (minimal):**
    -   View users, invoices, usage; basic logs (from Supabase analytics and Sentry).
6)  **PDF export & sharing:**
    -   HTML-first templates rendered to PDF (Supabase Function worker).
    -   Shareable, access-controlled links (using Supabase Storage signed URLs).
7)  **Evidence provenance UI:**
    -   Panel showing sources used (URL, snippet, retrieval score).
    -   Allow user to remove or edit sources before exporting.

Should-have (post-MVP)
- Strategy builder (positioning, acquisition plan) derived from ICP.
- Template library & downloadable templates (Notion, Loom workflows).
- Team workspaces and role-based permissions.
- Basic cohort/coaching features (Telegram/WhatsApp integration).

Nice-to-have (future)
- Hybrid LLM options / specialized models for cost savings.
- Marketplace for templates & community plug-ins.
- Advanced analytics / A/B testing support.

Prioritized User Stories & Acceptance Criteria
US-001: As a user, I can sign up and create a project so I can generate an ICP.
- Acceptance: User can register, verify email, and create a named project. Auth UI provided by SaaS starter, backed by Supabase Auth.

US-002: As a user, I can input a company or seed data and generate an ICP with sources.
- Acceptance: Generation completes (or queues) via Supabase Functions, and output includes sections and at least 3 source URLs per major claim. PDF export must include "Sources" section.

US-003: As a user, I can purchase a one-off ICP report or subscribe to monthly usage.
- Acceptance: Stripe / Razorpay checkout completes (UI from SaaS starter, webhooks via Supabase Edge Functions); user access is updated in Supabase Postgres.

US-004: As a user, I can generate ad copy variations based on generated ICP.
- Acceptance: System produces 3 ad variants per channel with source grounding (powered by OpenRouter via LLM Adapter).

Technical approach (MVP)
- **Frontend:** Next.js (React + TypeScript) deployed on Vercel. UI kit: TailwindCSS / `shadcn/ui`. **SaaS Starter Template** for rapid feature development and pre-built SaaS components.
- **Auth / DB / Storage / APIs / Workers:** **Supabase** (Auth + Postgres with `pgvector` + Storage + Edge Functions + Functions) for a fully integrated, low-ops backend.
- **Vector DB:** **Supabase Postgres with `pgvector`** for embeddings and retrieval, simplifying infrastructure and reducing cost.
- **Embeddings & LLM:** **OpenRouter** (configurable via adapter layer, implemented as a Supabase Function) for model flexibility and cost control.
- **Background jobs:** Postgres-based queue within Supabase Postgres, processed by **Supabase Functions** (workers).
- **PDF generation:** HTML templates rendered via Headless Chrome (Puppeteer) in a **Supabase Function** worker.
- **Hosting & infra:** Vercel for frontend; Supabase (hosted tier) for all backend, data, and compute.

Domain-specific considerations from ICP PDF
- Payment friction is a primary barrier. Ensure INR pricing (handled by frontend, passed to Razorpay) and UPI / Razorpay available at checkout.
- Mobile-first flow: prioritize responsive UI and light-weight exports (PDFs and short previews), supported by the SaaS starter template.
- Evidence & local case studies: provide UI to surface India/EM-specific sources and sample case studies in the report.
- Community channels: WhatsApp/Telegram integration (via Supabase Functions) is high-impact but can be deferred post-MVP.

Minimal data model highlights (high-level, all in Supabase Postgres)
- `users` (id, email, name, plan, billing_id)
- `projects` (id, user_id, name, settings)
- `icp_reports` (id, project_id, status, prompt_inputs, output_json, pdf_url, created_at)
- `embeddings_meta` (id, chunk_id, embedding `vector(1536)`)
- `jobs` (id, type, payload, status)
- `provenance_mappings` (id, report_id, claim_path, chunk_id, source_id, snippet_text, retrieval_score)

Cost estimates & budget guidance (target < $1,000/mo)
- Vercel Hobby / Pro: $0–$40.
- **Supabase (Auth + Postgres + pgvector + Functions + Edge Functions + Storage):** $50–$200 for reasonable usage (replaces costs from separate Pinecone, Redis, and Cloud Run).
- **OpenRouter:** Dominant cost. For conservative usage (1k ICPs/mo with optimized prompts / batching), estimate $200–$700/month (high variance depending on models chosen). Implement prompt budget/quotas.
- Stripe / Razorpay fees: variable per transaction (~2–4% + fixed).
- Total: Realistic initial runway under $1,000/mo if LLM usage is controlled and Supabase resources are optimized.

Risk & mitigation
- LLM cost overruns: add usage quotas, warn users on expensive operations, and offer lower-cost plans (cached templates), managed via Supabase.
- Hallucinations: require RAG grounding (`pgvector`), attach source snippets; expose provenance panel to users.
- Payment friction in India: integrate Razorpay/UPI and display INR pricing (frontend + Supabase Edge Functions).

Deployment & roadmap (Accelerated 4-week sprint plan)
W0: Setup repositories, Supabase project, Vercel, OpenRouter keys, Stripe/Razorpay. CI skeleton.
W1: Implement Auth (SaaS starter UI + Supabase Auth), Project CRUD (Supabase Postgres/Edge Functions), basic job enqueue (Supabase Postgres/Edge Functions).
W2: Implement RAG pipeline: ingestion (Supabase Function scrapes/uploads to Supabase Storage), chunking, embedding (LLM Adapter -> OpenRouter), index into `pgvector`, simple find+prompt (Supabase Function).
W3: Build PDF templates and export (Supabase Function); add provenance panel in UI; ensure job status updates (Supabase Realtime/polling).
W4: Integrate Payments (Stripe/Razorpay via SaaS starter/custom) and gating flows; add basic admin metrics; prompt tuning; E2E hardening.
Post-MVP: Iterate on complex connectors, additional content generation, team features, advanced analytics.

Acceptance criteria for launch (MVP)
- Users can sign up and create a project.
- ICP generator returns structured ICP with at least three evidence sources per major claim and exports to PDF.
- Payment flows successfully process a purchase and unlock gated features.
- Basic ad/content generation works and is linked to ICP outputs.
- Admin can view usage metrics and perform basic user and billing operations within the Next.js admin dashboard.
