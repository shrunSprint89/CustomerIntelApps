# MVP Plan: Scope, Prioritization, Roadmap & Checklist (Simplified for MVP Phase 1)

## Purpose
This document consolidates the minimal viable product (MVP) scope, prioritized features, detailed requirements, and an accelerated roadmap for the Elsa-like AI marketing assistant. It reflects a highly simplified, Supabase-first architecture, leveraging a Next.js SaaS starter template and OpenRouter for LLM integration. The goal is rapid, cost-efficient delivery of an evidence-backed ICP generator.

## 1. MVP: Scope & Prioritization

### Overview
This MVP focuses on the core ICP generator functionality, delivering evidence-backed reports with provenance and PDF export. It leverages a SaaS starter template for common features, maximizing Supabase for backend services, and OpenRouter for flexible LLM integration to keep operations lean and costs under $1000/month for initial scale (1k–5k MAU).

### Goals
- Deliver a working ICP generator that produces evidence-backed, exportable reports (PDF/HTML) with provenance links and citations.
- Reduce time and manual research for marketers and consultants while avoiding hallucinations.
- Provide a minimal workspace, billing, and admin features for Phase 1; expand to strategy and content tools in Phase 2.

### Sources & Assumptions
- Primary product reference: https://www.m1-project.com/
- Example ICP and requirements derived from: [`docs/Ideal customer profile Nomad Foundr.pdf`](docs/Ideal customer profile Nomad Foundr.pdf:1)
- Preferred stack: Vercel + Supabase, OpenRouter for LLMs, `pgvector` for vector DB.

### MVP Principles
1.  **Evidence-first:** Every claim must link to source snippets and URLs (provenance), stored in Supabase Postgres.
2.  **Fast-to-market:** Favor managed services (Supabase ecosystem, Vercel) and SaaS starter templates that reduce ops and accelerate development.
3.  **Cost-aware:** Optimize LLM usage (via OpenRouter) and utilize Supabase `pgvector` to keep costs low.
4.  **Extensible:** Build adapter layers for swapping LLM providers and maintain modularity for future growth.

### Must-have features (MVP Phase 1)
1)  **User onboarding & authentication:**
    -   Email sign-up, verification, password reset (leveraging SaaS starter UI, backed by Supabase Auth).
    -   Basic project/workspace creation via Next.js frontend interacting with Supabase Edge Functions.
    -   Subscription management and billing flows (via SaaS starter UI, integrating Stripe + Razorpay).
2)  **ICP Generator (core):**
    -   Accept seed inputs: company name, URL, industry, short description.
    -   Retrieval-augmented generation (RAG) pipeline:
        -   Web sources and user-uploaded docs ingested and indexed by Supabase Function workers into Supabase Postgres with `pgvector`.
        -   OpenRouter (via LLM Adapter) for LLM prompting that outputs structured ICP sections (Segment, Persona, Jobs, Goals, Channels, Sources).
    -   Attach source snippets and URLs for each generated claim (provenance stored in Supabase Postgres).
    -   Export ICP as PDF and JSON (generated by Supabase Functions, stored in Supabase Storage).
3)  **Content & Ads generator (basic):**
    -   Short-form captions, ad copy, and a 3-variant ad set per ICP (powered by OpenRouter via LLM Adapter).
    -   Basic channel-optimized outputs (LinkedIn, Instagram, Facebook).
4)  **Payments & gating:**
    -   Stripe Checkout for cards (integrated via SaaS starter).
    -   Razorpay or UPI for Indian buyers (custom integration).
    -   Subscription / one-off purchase gating, managed by Supabase and frontend logic.
5)  **Admin dashboard (minimal):**
    -   View users, invoices, usage; basic logs (from Supabase analytics and Sentry).
6)  **PDF export & sharing:**
    -   HTML-first templates rendered to PDF (Supabase Function worker).
    -   Shareable, access-controlled links (using Supabase Storage signed URLs).
7)  **Evidence provenance UI:**
    -   Panel showing sources used (URL, snippet, retrieval score).
    -   Allow user to remove or edit sources before exporting.

### Should-have (post-MVP)
- Strategy builder (positioning, acquisition plan) derived from ICP.
- Template library & downloadable templates (Notion, Loom workflows).
- Team workspaces and role-based permissions.
- Basic cohort/coaching features (Telegram/WhatsApp integration).

### Nice-to-have (future)
- Hybrid LLM options / specialized models for cost savings.
- Marketplace for templates & community plug-ins.
- Advanced analytics / A/B testing support.

### Prioritized User Stories & Acceptance Criteria
-   **US-001: As a user, I can sign up and create a project so I can generate an ICP.**
    -   Acceptance: User can register, verify email, and create a named project. Auth UI provided by SaaS starter, backed by Supabase Auth.
-   **US-002: As a user, I can input a company or seed data and generate an ICP with sources.**
    -   Acceptance: Generation completes (or queues) via Supabase Functions, and output includes sections and at least 3 source URLs per major claim. PDF export must include "Sources" section.
-   **US-003: As a user, I can purchase a one-off ICP report or subscribe to monthly usage.**
    -   Acceptance: Stripe / Razorpay checkout completes (UI from SaaS starter, webhooks via Supabase Edge Functions); user access is updated in Supabase Postgres.
-   **US-004: As a user, I can generate ad copy variations based on generated ICP.**
    -   Acceptance: System produces 3 ad variants per channel with source grounding (powered by OpenRouter via LLM Adapter).

## 2. ICP-derived insights and architectural refinements

### Executive Summary
The ICP PDF shows Elsa-like outputs must be evidence-first, mobile-friendly, locally aware (India/EM), and payment-aware (INR/UPI). The report structure (Persona, Jobs-to-be-done, Goals, Problems, Sources, Channels) must be preserved, with provenance (URLs/snippets) for each claim. Key behavioral patterns from the PDF indicate a need for low-cost, high-trust validation tools, rapid actionable wins, and a frictionless payment experience.

### Top-level implications for the simplified architecture
1.  **Evidence & Provenance Everywhere:** Every generated claim must link to source snippet(s) and retrieval scores; store mappings in the `provenance_mappings` table within Supabase Postgres. UI exposes an editable provenance panel.
2.  **Mobile-First UX & Offline-Friendly Exports:** The app must be responsive; PDF/JSON exports for offline use. Frontend emphasizes SaaS starter with mobile-first design.
3.  **Local Payments & Pricing:** Support INR pricing and UPI/Razorpay flows. Integrations confirm Razorpay and Stripe via Supabase Edge Functions.
4.  **Source Types & Ingest Connectors:** Focus MVP Phase 1 on direct uploads (PDF/DOCX) and basic webhook-driven form connectors (Typeform/Tally). Supabase Functions normalize inputs into chunked passages with metadata.
5.  **"Fast Validation" & Two-Tier Generation Modes:** Offer "fast" (low token, small retrieval set) vs "deep" (paid) ICP generation. Supabase Functions workers tag jobs with mode and budget estimate.
6.  **Community & Cohort Integration (Post-MVP):** Export/scheduling hooks for WhatsApp/Telegram via Supabase Functions.

### Detailed changes to ML & retrieval pipeline
-   **Source Selection Bias:** Include country and region filters in `pgvector` metadata (`pgvector` for retriever).
-   **Evidence Thresholds:** Require N supporting snippets with min `retrieval_score` to mark claims as "high confidence" or "insufficient evidence."
-   **Provenance Schema Extension:** `provenance_mappings` table stores `{source_url, domain, snippet_text, retrieval_score, publication_date, source_type}` for full traceability.
-   **Caching & Re-use:** Cache embeddings and retrieval results by seed-hash in Supabase Postgres.

### Data Model Updates (Aligned with Supabase Postgres)
-   `icp_reports.output_json`: Extend schema to include "provenance_map" and "confidence_scores" per section.
-   `sources` table: Add columns (`source_type`, `language`, `region`, `published_at`, `raw_storage_path`).
-   `user_uploaded_documents` table: Manage user consent metadata (`consent_for_processing`, `consent_for_training`).

### UI & UX Requirements
-   **Provenance Panel:** Show top-k snippets per claim with domain, snippet, `retrieval_score` with toggles for export inclusion.
-   **Evidence Visual Cues:** Confidence badges (high/medium/low); "insufficient evidence" alerts and recommended actions.
-   **Payment Flows:** Inline Razorpay widget for INR; clear messaging about refunds and local support.

### Integrations & Channel Strategy
-   High priority for MVP: Razorpay, Stripe, basic webhook-driven connectors (Typeform/Tally).
-   All backend integration logic implemented as Supabase Functions or handled by Supabase Edge Functions for webhooks.

### Security, Privacy & Legal Implications
-   Explicit consent tracking: users must consent to processing uploaded docs; store consent timestamps and allow revocation in Supabase Postgres.
-   Opt-out training: default to not using private user content for model training unless opted in.
-   PII handling: redact contact data from snippets stored for retrieval, or store pointers (hashes) and show redacted snippets in public contexts.

### Operational & Performance Implications
-   Expect variable load; use Postgres-based job queuing and quota enforcement (Supabase Functions/Edge Functions) for LLM bills.
-   ETA estimation: provide queue position and estimated time-to-completion; surface cost estimate prior to starting.

### Acceptance Criteria Guided by the PDF
-   Generated ICP must include a "Sources" section with at least 3 unique domain citations per major ICP claim.
-   Exported PDF must reproduce the ICP structure and include provenance appendix.
-   Checkout must support INR and at least one local payment method (Razorpay or UPI) for India.

## 3. Requirements: Functional and Non-Functional

### Functional Requirements (MUST)
1.  **User Authentication and Account Management:** Email/password sign-up, verification, password reset (SaaS starter UI, Supabase Auth). Social SSO optional. Role-based access control.
2.  **Workspace & Projects:** Users create projects (`Supabase Postgres`). Project-level settings, history, and export.
3.  **ICP Generator (core):** Structured input, automated RAG pipeline (`Supabase Functions` + `pgvector` + `OpenRouter`), structured ICP output, PDF/JSON export with provenance.
4.  **Editable ICP Template:** Customizable template for output formatting.
5.  **Export & Reporting:** PDF reports (Supabase Functions), shareable links (Supabase Storage).
6.  **Payments & Billing:** One-off purchases/subscriptions (SaaS starter UI), INR/USD payments (Razorpay/Stripe, currency conversion options), invoices/receipts.
7.  **Admin Dashboard:** User/billing management, model usage, content moderation (Next.js frontend + Supabase).
8.  **Evidence Traceability:** LLM-based claims linked to source snippets in `provenance_mappings`. Human-editable evidence panel.
9.  **Data Export/Import:** Export ICPs; import user-provided datasets.
10. **Audit, Logging, Quotas:** Track generation events, limits, billing metrics.

### Functional Requirements (Phase 2 / SHOULD)
- Strategy Builder, Content & Ads Generator, Template Library, Live cohort features (Telegram/WhatsApp), Advanced Integrations (Notion, Loom, Typeform, Tally, Zapier), Team accounts, Fine-grained versioning.

### Non-Functional Requirements
-   **Performance:** UI < 200ms, ICP generation 5–30s (fast prompts), background for "deep" runs.
-   **Scalability:** Horizontal scaling for Supabase Edge Functions/Functions. `pgvector` in Supabase Postgres for millions of documents initially.
-   **Availability & Reliability:** Target SLA 99.9% for core flows. Graceful degradation for heavy ML jobs.
-   **Security and Privacy:** TLS, encryption at rest for user data, Supabase Secrets for keys. Per-tenant data isolation (Supabase RLS). Minimal PII, GDPR-compliant data deletion.
-   **Maintainability:** Modular Supabase Functions/Edge Functions with clear contracts and tests.
-   **Cost:** Predictable cloud costs with managed Supabase services.

### Data and ML-specific Requirements
-   Provenance store: generated section links to retrieved sources (URL + snippet + retrieval score).
-   Vector store: `pgvector` in Supabase Postgres for embeddings storage.
-   Dataset management: ingest pipelines (`Supabase Functions`), deduplication, metadata, update cadence.
-   Model orchestration: OpenRouter via adapter (`Supabase Function`) for swapping LLM providers.

### Compliance, Legal, and Privacy
-   Data processing agreements, consent for user data in model training.
-   Opt-out of user data reuse for training by default.

### Observability and Operations
-   Centralized logging (Supabase logs), metrics (Supabase native, custom from functions), traces (OpenTelemetry for Supabase Functions/Edge Functions).
-   Business-level KPIs: MAU, conversion rate, time-to-generate ICP, cost-per-generation.
-   Alerting for LLM failures, job queue backlogs (Postgres), payment failures, SLA breaches (Supabase monitoring and Sentry).
-   **Analytics:** Google Analytics, Tag Manager, Metapixel for marketing attribution.
-   **Emails:** Transactional and marketing emails (adapter integration).
-   **Affiliate Marketing:** Platform for tracking and managing affiliate programs.

## 4. Roadmap: Accelerated 4-week Plan & Beyond

### Accelerated Goal
Deliver a robust ICP JSON generation pipeline (RAG + OpenRouter LLM) with provenance stored in Supabase Postgres within 4 weeks (30 days). Provide minimal UI via SaaS starter, with PDF export integrated.

### Success Criteria (30-day target)
- Users can sign up, create a project, submit seed input, and receive a structured ICP JSON with provenance.
- Generated JSON conforms to schema and includes source citations.
- Basic quotas and cost controls (via OpenRouter LLM adapter) prevent runaway LLM spend.
- Core payment flows (Stripe/Razorpay) are functional.

### Team & Roles (Current)
- **Senior Engineer:** Reviews code, security sign-offs, critical integration testing (part-time).
- **Roo-code agent (this automation):** Orchestrator, architect, coder, debugger; continuous.
- **Product Manager (PM):** Product decisions, prioritization, user testing coordination.

### Assumptions for Accelerated Schedule
- Roo-code agent handles majority of implementation. Senior Engineer focuses on review.
- PM provides seed inputs and coordinates beta test cases.

### 4-Week Plan (High Level)
-   **Week 0 (2–3 days) — Setup & Skeleton:** Provision accounts (Vercel, Supabase, OpenRouter, Stripe/Razorpay). Create monorepo layout (`/web`, `/supabase`, `/infra`). Seed test inputs.
    -   *Deliverable:* Dev environment set up with Supabase CLI and Vercel connected.
-   **Week 1 — Core Auth, Project Model, Enqueue (7 days):** Integrate Supabase Auth (SaaS starter UI). Implement Project CRUD (Supabase PostgREST/Edge Functions API + minimal UI). Implement job enqueue via Supabase Edge Function (`jobs` table trigger `Supabase Function`).
    -   *Deliverable:* User can create a project and initiate an ICP generation job.
-   **Week 2 — Ingestion, Embeddings & RAG (7 days):** Implement source ingestion (`Supabase Function` for web scraping/document upload). Chunking, deduplication, compute embeddings via LLM Adapter (OpenRouter) on `Supabase Function`. Upsert embeddings to Supabase Postgres with `pgvector`. Implement RAG retrieval (`pgvector`), assemble prompt with snippets, and call OpenRouter LLM via adapter on `Supabase Function`.
    -   *Deliverable:* ICP structured JSON generated with RAG, provenance stored.
-   **Week 3 — Payments, PDF Export & UI Enhancements (7 days):** Integrate Payments: Stripe (SaaS starter) + Razorpay (custom UI) with Supabase Edge Functions for webhooks. Build PDF templates and implement PDF export (`Supabase Function`). Add provenance panel in UI. Implement job status updates (Supabase Realtime/polling).
    -   *Deliverable:* Functional payment flows, PDF export, and enhanced UI for ICP review.
-   **Week 4 — Testing, Tuning & Stabilization (7 days):** Add unit tests for Supabase Functions/Edge Functions and E2E smoke tests. LLM prompt tuning (OpenRouter). Implement basic token accounting and per-user quotas (Supabase Edge Functions/RLS); add simple admin metrics.
    -   *Deliverable:* Release candidate for MVP, ready for beta testing.

### Minimal Scope & Tradeoffs
- Focused on JSON output with provenance and integrated payment flows.
- Uses Supabase and OpenRouter for cost-efficiency and operational simplicity.
- Leverages SaaS starter template to accelerate common UI components.

### QA & Validation
- PM provides 10 representative seed inputs.
- Automated regression tests for output schema and provenance.
- Senior Engineer reviews sample outputs and approves readiness.

### Post-30-Day Actions
- Week 5–6: Enhance connectors, add more content generation features.
- Week 7–8: Integrate advanced analytics, explore A/B testing frameworks.
- Continue beta with selected users.

### Risks & Mitigations
- **LLM cost:** Enforce quotas, use cheaper models (via OpenRouter), monitor token usage.
- **Hallucination:** Require RAG grounding (`pgvector`), attach source snippets, expose low-confidence flags.
- **Integration blockers:** Use Supabase Edge Functions for webhooks, implement adapter patterns for external providers.

- E2E tests pass in CI.
- Senior Engineer has reviewed and signed off critical flows.

## 5. Phase 1 Development Checklist

### Minimal Deliverables (MUST)
1.  **Auth & Projects:**
    -   Integrate auth using Supabase Auth (leveraging SaaS starter template UI).
    -   Implement Project CRUD via Supabase PostgREST and Edge Functions where needed.
2.  **Generate API endpoint:**
    -   Supabase Edge Function (e.g., `api/generate_icp`) accepts seed inputs, creates `icp_report` in DB, and enqueues job in Postgres-based `jobs` table, triggering a Supabase Function.
3.  **Supabase Functions (Workers):**
    -   Implement Supabase Functions for all worker tasks: source ingestion, chunking, embedding, retrieval, LLM invocation, result persistence (to Supabase Postgres), and PDF generation.
4.  **LLM Adapter (OpenRouter-centric):**
    -   Implement LLM Adapter as a Supabase Function (`supabase/functions/llm-adapter.ts`) that calls OpenRouter for both embeddings and generation.
    -   Store prompt templates (e.g., `ml/prompts/icp_v1.json`) within the Supabase functions project.
5.  **Persistence (Supabase Postgres with `pgvector`):**
    -   Ensure `icp_reports` table has fields: `id`, `project_id`, `status`, `output_json`, `token_usage`.
    -   `embeddings_meta` table uses `pgvector` to store embeddings for RAG.
    -   `provenance_mappings` table stores source citations for evidence.
6.  **Frontend minimal UI (Next.js with SaaS Starter):**
    -   Leverage SaaS starter for user auth, dashboard.
    -   Provide a form to submit seed inputs and a viewer to display `output_json` and provenance.
7.  **Testing & CI:**
    -   Add unit tests for Supabase Functions/Edge Functions and LLM Adapter.
    -   E2E smoke test: signup -> generate -> retrieve report.
    -   CI workflow skeleton: `.github/workflows/ci.yml` (for Vercel & Supabase CLI deployments).
